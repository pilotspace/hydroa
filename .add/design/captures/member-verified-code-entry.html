Section 3 — Error states

Calm, inline, recoverable — never a loud red alarm

Every code failure is a quiet role="status" message under the segments (reusing the dns-verify-softeners calm-state pattern) — not a role="alert". Expired and too-many both offer a one-tap "Resend code". The segments stay put so the user can correct without losing context.

Invalid code — ERR_MEMBER_VERIFY_CODE_INVALID (400)
419 207
That code doesn't match. Double-check the 6 digits from your email and try again.
Expired code — ERR_MEMBER_VERIFY_CODE_EXPIRED (410)
This code has expired. Codes are valid for a short window — request a fresh one. ↻ Resend code
Too many attempts — ERR_MEMBER_VERIFY_TOO_MANY_ATTEMPTS (429)
Too many tries on this code. For your security we've paused it — send a new code to start over. ↻ Resend code
loud red role="alert" → deliberately avoided; a mistyped digit is not an emergency.

Also handled the same calm way: ERR_RATE_LIMITED (429, Retry-After), ERR_DOMAIN_CLAIM_NOT_PENDING (409), ERR_MEMBER_VERIFY_DOMAIN_MISMATCH (403), 404. The UI only ever sends the code — never an email or domain.
