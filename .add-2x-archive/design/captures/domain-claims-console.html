Grounding notes carried into this wireframe

  • Status chip = the immutability-marker idiom. The Verified seal reuses InvoiceStatusSeal.tsx / BundleEvidenceSeal.tsx verbatim — a Badge variant="success" + lock + sr-only ownership assertion, mono/tabular per badge.tsx. Verified reads as "sealed / final ownership".
  • Only two statuses are persisted: ClaimStatus = pending | verified (DB CheckConstraint status IN ('pending','verified')). Expired is derived client-side (pending && expires_at < now); a failed Verify now is an ephemeral result (claim stays pending), not a stored "failed" state; revoke is a hard DELETE — the row simply disappears (no tombstone chip).
  • No new BFF route. The console calls the existing authenticated proxy (/api/gw/[...path] via bffGet/bffPost/bffDelete) against the frozen gateway API; owner-only is enforced server-side (403 ERR_AUTH_FORBIDDEN).
  • Home: a new "Domains" tab in the existing SettingsPage.tsx hub (URL-controlled ?tab=domains), alongside SSO / SAML — all owner-scoped surfaces.
